## 通用执行约束

- 复用 Express、Postgres 和现有账号会话；不迁移若依模板，不重置账号/数据库。
- 新业务前端单独放在 `gym/` 模块；根 `index.html` 只增加进入新模块的入口，不承载新业务状态和页面。
- 数据库只做向前兼容的新增表/索引，迁移可重复运行；不重建或改写 `users`、`workout_records`。
- 所有业务 API 在服务端按角色、当前教练关系和资源归属授权。先验证拒绝路径，再连接界面。
- 训练图片存于非静态私有目录，下载通过授权 API。仅允许图片 MIME、大小和文件名经服务端校验。
- 只使用专用测试账号和记录。不得清空浏览器存储、覆盖真实训练记录或重启/另起服务。
- 保留用户已有工作区修改。Git 默认只读。

## 阶段 1：权限、邀请和管理员基础

**后端模块**：新增 `server/db/` 迁移与查询层、`server/modules/identity/`、`server/modules/coaching/`，在 `server/server.js` 以路由模块挂载；新增 `user_roles`、`coach_student_relationships`、`coach_invitations` 表。注册账号默认只具备学员/普通用户身份；首个 `yhone` 管理员角色通过幂等迁移写入，后续教练资格只能由管理员授予。

**接口范围**：当前用户与角色、管理员授予/撤销教练角色、教练创建/撤销/接受邀请、当前教练关系、学员列表。邀请用随机不可猜测 token、有效期和一次性状态；创建、接受均事务化，数据库约束保证每位学员最多一个有效教练。

**阶段验收**：普通账号不能访问管理/教练 API；学员不能接受过期/已用邀请或关联第二位教练；教练 A 无法查教练 B 的学员；非管理员不能授予角色；`yhone` 能访问管理能力。重复运行迁移不改现存训练数据。

## 阶段 2：动作库、模板与计划版本

新增 `server/modules/catalog/`、`server/modules/plans/` 和 `gym/catalog/` 管理界面。管理员编辑动作库；教练只读搜索。由开发方从 `ExerciseGymGifsDB-main` 选取并检查常用动作，准备约 80–120 条结构化种子数据及本地 GIF，字段含中文名、肌群、器械、模式、动作提示、分化归类和媒体路径。导入使用稳定 slug/upsert，不覆盖管理员后来编辑的记录。

创建推拉腿、上下肢、五分化模板和模板动作明细；教练可复制模板形成学员计划，按日编辑动作顺序、组数、次数、RIR、可选重量和时长。计划发布生成不可变版本快照；开始后的训练引用快照。

**阶段验收**：动作查询/筛选正确，GIF 与名称一一对应；角色不能编辑越权数据；三类分化均可建立可发布计划；发布新版本不改变旧训练快照。

## 阶段 3：训练日志、草稿和身体记录

新增 `server/modules/sessions/`、`server/modules/measurements/` 和对应学员/教练页面。记录计划快照、开始/结束、状态、逐组重量/次数/RIR、备注、跳过/替换。草稿按会话自动保存，放弃只删除本草稿；完成记录通过追加更正事件保留审计轨迹。学员只读。

身体数据支持学员/教练录入并标明录入者；初始记录进入待学员确认状态，确认后数据库拒绝修改；之后新建测量点。体脂可空，不由 BMI 估算。进阶建议只生成建议，教练确认后创建下一计划版本。

**阶段验收**：刷新恢复草稿；放弃草稿不影响既有完成数据；确认后的初始值不可更新；每组记录与报告一致；更正有审计轨迹；学员端没有写权限。

## 阶段 4：照片审核和展示圈

新增私有文件存储适配器、本地持久目录配置及 `server/modules/media/`、`server/modules/feed/`。图片默认私有；管理员审核后按 `self`、`coach`、`public` 授权读取。改公开需重新审核；撤回应立即阻断文件访问和 feed 可见性。展示圈只查询审核通过、未撤回的公开照片，登录用户可按时间浏览并点赞；点赞唯一约束防止重复。

**阶段验收**：匿名、无关教练、其他学员均不能通过 API 或猜路径读取私密图；待审核图片不在 feed；撤回后文件 API 立即拒绝；管理员审核记录可追踪；公开照片仅站内登录用户可看；点赞/取消点赞状态正确。

## 阶段 5：入口、联测和兼容回归

根 `index.html` 增加“健身房训练”入口，角色登录后由 `gym/` 模块显示相应工作台；管理工作台把动作库和照片审核分为独立菜单。验证手机与桌面布局。对旧账号登录、`/api/state` 同步、迁移旧数据和全部旧居家训练键做回归。

**验收**：基于真实使用流程联测管理员→教练→学员；每个越权场景均由服务端拒绝；旧首页功能/数据无回归。运行静态校验与模块测试。若当前容器未包含修改后的后端，本轮仅报告构建/静态验证，不擅自重启；运行态端到端验收待用户明确安排服务重启。
